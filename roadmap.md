| RM-68 | Alembic migrations for the gateway database | done | `create_tables()` now runs migrations; a database predating Alembic is lifted to the baseline and stamped rather than re-created, so RM-70 can alter tables holding real usage and billing rows. | RM-69 | Replica failover, active health checks, and group-based pricing | done | Today a replica adds neither throughput nor fault tolerance: the circuit breaker is checked only on the deterministic pick, retries hammer the same dead instance, and routing by instance id escapes both pricing and the spend cap |
| RM-70 | Model/instance identity: immutable slug, opaque ids, per-model label | done | Catalog `slug` (public, immutable), `name` and `modality`, plus a per-model instance `label`; old ids kept as aliases so nothing broke. Opaque primary keys deliberately not done — the detail section says why |
| RM-71 | Replica UX: "Add instance" flow and a model-level scope picker | done | Creating a replica should ask only node/engine/port and auto-increment the label; the scope picker should list models with a replica-count pill, never individual instances |
| RM-72 | Gateway: intelligent load balancing across replicas | done | Absorbs RM-58. Least-in-flight, normalised by each backend's reported concurrent slots, verified live. Session affinity deliberately not built — the detail section carries the measurements behind that call |
| RM-73 | Billing traceability per replica + per-model metrics rollup | done | `usage_events` records which replica served alongside the model id and slug; metrics gain a per-model aggregate so the dashboard can show a model's throughput rather than N loose instance rows |

| RM-74 | Retired model names are never reused | done | Deleting a model now archives it instead: it stops routing, listing and accepting instances, but keeps its row. Usage is billed against the slug and `model:<slug>` grants are written against it, so recycling a name would merge two models' invoices and silently transfer every client's access; restoring is the escape hatch |
| RM-75 | fix: manager registry path resolved against the process's cwd | done | `[registry].path` is relative, so `resolved_registry_path` returned a cwd-relative path — any `pmgr` command run from `runtime/manager/` silently created and wrote to a nested `runtime/manager/runtime/manager/registry.db` instead of the real registry; relative paths now anchor to the repo root, absolute ones (the container's `PMGR_REGISTRY_PATH=/data/...`) are untouched |

| RM-76 | A manually registered model can't be archived | done | `DELETE /v1/models/{id}/downloaded` refuses anything not downloaded through that flow and `DELETE /v1/backends/{id}` only removes an instance, so a hand-registered model's catalog row can never be retired — which now matters, since archiving is what keeps a published name from being reused (RM-74) |

| RM-77 | fix: the response body named the replica, and `context_length: 0` was ambiguous | done | llama.cpp echoes its own `--alias` as `model`, so the body reported an instance id that isn't in the catalog — anyone attributing cost by `response.model` split one model's spend across replica names; the body now names the model on every endpoint and every streamed chunk. Image models advertise `context_length: null` instead of `0` |
| RM-78 | Idempotency keys for inference requests | done | Without them a client retry is always a new, billable generation, so an SDK can only retry where the platform proves nothing ran — which excludes the commonest case, retrying after its own timeout. Raised by the Axonium SDK team |

| RM-79 | The bare-metal stack has no Redis of its own | done | `podman-compose.yml` deliberately doesn't publish 6379 — Redis is internal to the container network — so a host-run gateway silently used whichever container happened to publish the port. When that unrelated container stopped, every authenticated request started failing closed with `401 invalid-token`. Needs a dev Redis that belongs to this project, and something that notices when it's gone |

| RM-80 | fix: idempotency refusals shared one error type | done | All four reasons answered `409 idempotency-conflict`, so telling them apart meant matching on prose — and they need opposite handling: only "still running" resolves by retrying. Each now has its own `type`, and a malformed key is a 400 rather than a conflict it never had |

| RM-81 | Idempotency: distinguish refusals by type, and estimate the wait | done | Follow-on to RM-80: `idempotency-in-progress` now carries a `Retry-After` derived from the model's observed p95 latency minus elapsed time. The earlier refusal to provide one claimed the only bound available was the 600s backend timeout, which was wrong — the measurement already existed |
| RM-82 | Idempotency for streaming responses | done | A streaming retry still regenerates and bills twice — the same exposure RM-78 closed for non-streaming, left open in what is likely the busier path. A stored key can cover a dropped client connection but not a stream the model itself broke; covering that needs resumption (SSE `Last-Event-ID`), which no comparable platform has built |
| RM-83 | Mark an interrupted stream on the usage row | done | A stream that broke after producing tokens is still billed for what it generated — as every comparable platform does, since the compute was spent. What was missing is the record: a client disputing the charge had nothing to point at, and neither did we. Building it surfaced that interrupted streams were billed as zero and left no row at all, because llama.cpp only reports token counts on the final frame — fixed here too |
| RM-84 | fix: the manager's JWKS URL pointed at a path that does not exist | done | Two wrong defaults — `/v1/jwks` is a 404, and `localhost:9000` is answered by whatever else on the machine is bound to `0.0.0.0:9000`. Either way the manager rejected every token as "invalid or expired", naming credentials as the culprit instead of the URL |
| RM-85 | fix: the manager blamed the caller for its own outage | done | A JWKS it could not fetch was reported as `401 Invalid or expired token`, sending the investigation to the credentials — the one place the problem was not. Unreachable is now a `503` with `Retry-After`; actually-invalid stays `401`. Exposed a test that had never tested token validation |
| RM-86 | registry.db is runtime state, not seed data | done | It was the one `.gitignore` exception, justified as committed seed data. It stopped being that — it became the live catalog, mutated on every change and holding 26 absolute paths from one machine in a public repo. Now ignored like the other databases, with `registry.db.example` as the committed seed, matching the `.env.example` convention already used two rules below |
| RM-87 | fix: a streamed request was only accounted for if the client drained the body | done | Found from an Axonium report about unreliable streaming replay. The cause was larger: we sent two `[DONE]` frames, a client correctly stopped at the first, and everything after it — billing, metering, idempotency, budget settle — ran inside a task the server then cancelled. Streamed generations to any normal SDK were free |
| RM-88 | Usage rows say *why* a request stopped, not just that it did | done | `interrupted` could not tell an answer we broke from one the caller walked away from, which are opposite conversations when a charge is questioned — and a chat UI's stop button produces the second all day. `termination_reason` names all three; the published boolean stays, derived, meaning exactly what we told SDK clients it means |
| RM-89 | `family` is never stored empty | done | Both registration paths defaulted it to `""`, which is indistinguishable from nobody filling it in — an SDK team asked about the same blank field four rounds running. The registry now fills it at the single chokepoint, reading the GGUF's `general.architecture` when a caller supplies nothing, and `unknown` when even that is unreadable |
| RM-90 | Honour `OTEL_RESOURCE_ATTRIBUTES` | done | Requested by the Argus team, who supplied the patch and the tests. `Resource(attributes=...)` silently drops the standard variable, so telemetry arrived without the application grouping and no service could be placed under its platform. `Resource.create()` merges it; explicit attributes still win |
| RM-91 | Retire the self-hosted observability stack | done | Monitoring moves to Argus, who centralise it across all the owner's applications. Stage 1 done: Loki, Promtail, Tempo and our own Grafana removed from both compose files, `observability/` deleted, and the Grafana secrets dropped from the installers and validators. Instrumentation stays — Argus asked us to keep it |
| RM-92 | Remove what the retired stack left behind | done | Stage 2, and the end of it: the hardcoded `tempo:4318` default, `grafana_url`, the unused `ops:dashboard` scope, and the orphaned DGX compose file. Nothing configured now means export nowhere, which also ends the retry storm that cost ~45% of the pre-push hook |
| RM-93 | Services identify themselves to Argus | done | `manager-api` and the terminal UI both announced themselves as `manager`, so a running TUI kept the API looking alive to a silence probe. Renamed, and every service now carries `OTEL_SERVICE_NAME` and a `service.namespace` in compose and the env examples — nothing did before, which is why only the one service Argus ran by hand had ever been identified |
| RM-94 | Telemetry env vars go where they are actually read | done | RM-93 put the identity in each service's `.env`, where it does nothing: those files are parsed by pydantic-settings and never reach `os.environ`, which is where the OTel SDK looks. Measured, not assumed. Moved to `runtime/telemetry.env`, and added what Argus asked for — stable HTTP attribute names, `service.version`, `service.instance.id` |
| RM-95 | Health probes ask where the engine answers, and stop tracing themselves | done | A 404 was being read as proof of life, which cannot tell a healthy backend from a different process holding the port — a failure we hit on this machine the same week. sd.cpp answers `GET /` with 200; nobody had looked. Probe spans were 57% of the gateway's telemetry and are now suppressed at source. GenAI attributes emitted by hand rather than taking a dependency |
| PRM-96 | The SDK must reach only the gateway, never auth-service | done | Clients are told to fetch tokens from `auth-service` directly, so the service that issues credentials has to be reachable from wherever a client runs — a second public surface with its own auth, CORS and ways to get it wrong. Everything should enter through the gateway |
| RM-97 | Blocking query instead of a 30s poll for the catalog | done | The gateway polled the manager every 30s, so a backend appearing or leaving took up to half a minute to be routable — which is why active health probing had to exist at all. The manager now holds the request until the registry stops matching the index the caller holds. Measured end to end: 1.2s |
| RM-98 | A manager outage empties the gateway's routing table | done | A failed sync replaces the catalog with `[]`, so the gateway serves zero models until the manager returns — an inference outage caused by a control-plane component. The copy exists precisely so the control plane is not on the data plane's critical path, and today it does not deliver that |
| RM-99 | The last catalog survives a gateway restart | done | RM-98 kept a manager outage from stopping a *running* gateway, leaving the case that matters most uncovered — a gateway restarting while the manager is down, which is exactly what a deploy is. The catalog is now kept in `gateway.db` and read only when a start finds no manager; the moment the manager answers, its answer replaces it |
| PRM-100 | A client can read the usage row for its own request | in-progress | We told an SDK team that `termination_reason` gives a client disputing a charge something to point at, then put it behind `admin:read` — so only the party that does not need it can see it. Three columns missing, not one: the `request_id` we hand back on every response, the cached prompt tokens we report and never store, and a replay's link to the generation it replayed |
| PRM-102 | auth-service stops being published | done | PRM-96 moved token issuance to the gateway, leaving one surface an outsider still had to reach directly: the one-time credential page. Fronting it here closed that, and fixed a link that pointed at an internal hostname the recipient could never resolve. The container publishes no host port now — everything arrives through the gateway |
| PRM-103 | The server span carries HTTP attributes, opened by the ASGI instrumentation | done | Argus measured that our server spans were named `http.get` and carried nothing at all — so for auth-service and manager-api they recorded that a request happened and no more: no route, no status, no latency per endpoint, and therefore no RED metrics and no per-endpoint SLO. The span is now opened by `opentelemetry-instrumentation-fastapi`; `TraceIDMiddleware` keeps only its id. Inbound trace context stays ignored |
| PRM-104 | One CLIENT span for a model call, whichever way the caller asked | done | Argus reported `inference.request` as Internal. It was worse: the GenAI data arrived under two span kinds and two names depending on whether the caller asked for a stream, so their client-side RED metrics saw half the traffic and which half was the client's choice. Both paths now emit `chat <model>` as CLIENT; the INTERNAL span keeps describing the gateway's own work |
| PRM-105 | The model pair can finally differ, and first-token latency stops being a reasoning artefact | done | `gen_ai.request.model` and `gen_ai.response.model` both came from the resolved name, so the pair Argus uses to spot "asked for one model, served another" was empty by construction. And `ttft_ms` waits for visible output, which a reasoning model reaches last — present on 13 of 247 spans, the missing ones chosen by how much the model reasons |
| PRM-106 | Rerankers get the endpoint they need | done | A client filed three bugs — logprobs discarded, requests "hanging" 30-60s, a chat template needing manual prefill — that were one problem: a cross-encoder served as a text generator. llama-server refuses `/rerank` unless started with `--reranking`, and the gateway had no rerank modality or endpoint. `POST /v1/rerank` returns the relevance score the engine already computes, for the whole document set in one request |
| PRM-107 | The model file contradicts a wrong modality at registration | done | A reranker was registered as `text`, started without `--reranking`, and answered chat requests with plausible nonsense for weeks until a client reported three bugs that were one. The GGUF says what it is — `classifier.output_labels` and `pooling_type` — so a registration that disagrees with the file is refused rather than defaulted |
| PRM-108 | Modality is chosen in the dashboard, not guessed | done | Registering a downloaded model from the UI never asks for modality and silently defaults to `text`, the one value that never fails loudly. The field is already patchable on an existing instance; what is missing is showing it at registration with the inferred value preselected |
| PRM-109 | Modality belongs to the model, and is edited there | done | RM-70 put modality on the model row saying it made replicas disagreeing about it impossible, but the entry handed to the gateway kept reading the instance copy — so the guarantee never held, and correcting a mistake meant editing every instance. The catalog is now the only source; the instance PATCH refuses the field and names where to change it; the dashboard edits it on the Models page and shows it read-only on Instances |
| PRM-110 | Family and name are editable, and the button says what it does | done | The "Register model" button on Instances sends `model_id` — it creates an instance of a catalogued model and never registered a model at all, which also made PRM-109's "editable while registering" exception wrong. Family joins modality as editable on the model: RM-89 already noted the GGUF architecture is not always the lineage a human would name |
| PRM-111 | The model's display name is editable, and finally visible | done | PRM-110 made `name` patchable but never showed it: the Models table rendered `id`, the registry key that cannot change, so a model somebody had already named as "Qwen3 0.6B Instruct" still displayed its id. The table now shows the name with the routing slug beneath it, and the pencil edits the name |
| PRM-112 | The public name is set on the model, and the table says which name is which | done | `slug` was editable from the instance form — the same wrong place modality was. It names the model, so every instance answers to it. Moved to the model's pencil with RM-70's once-only rule intact. And the routing name under each row is now always shown and labelled `model:`, instead of appearing only when it differed from the display name with nothing saying what it was |
